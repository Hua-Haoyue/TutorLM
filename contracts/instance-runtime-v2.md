# Persistent Instance Runtime v2

本协议用于持久项目。一个 workspace 对应一个项目、一个持久卷；用户可以拥有多个 workspace。
匿名临时租约仍遵循 v1，不具有持久项目语义。容器内应用需要实现本协议才能接入持久模式。

## 资源归属

- `user_id`：用户 UUID。需要恢复凭据或用户 Cookie 验证，UUID 本身不是访问令牌。
- `workspace_id`：项目 UUID，独立于容器、槽位、租约、代次与应用会话。
- 项目卷由 workspace UUID 决定，不能由 slot、lease 或 session ID 决定。
- 每个项目同一时刻最多一个计算租约；同一用户的不同项目可以占用不同槽位。
- 容器只挂载当前项目卷，不挂载用户的其他项目或控制面数据库。
- 持久卷不属于 Compose 的临时实例生命周期，也不做容器文件系统快照。

## 应用配置与就绪

持久模式中，控制面在普通应用配置之外注入：

| 变量 | 约定 |
| --- | --- |
| `TUTORLM_PERSISTENT_WORKSPACE` | `true` |
| `TUTORLM_WORKSPACE_ID` | 当前项目 UUID |
| `TUTORLM_OWNER_ID` | 所属用户 UUID |
| `TUTORLM_DATA_DIR` | 与数据挂载点一致，默认 `/data` |

`GET /health/ready` 必须验证存储可用，并至少返回：

```json
{"status":"ok","storage_mode":"persistent","workspace_id":"<当前项目 UUID>"}
```

仅返回 `status=ok` 不足以进入持久模式。控制面会拒绝未确认项目绑定的应用镜像。
已初始化的卷缺失时必须报错，不得静默生成空卷冒充原项目。

## 应用数据与会话

应用应把当前项目的数据库、原始文件和学习产物写入 `/data` 下的稳定路径，
例如 `workspace.sqlite3`、`sources/`、`artifacts/`，不能只写入容器可写层或 `/tmp`。

应用 session 只授予当前 workspace 的访问能力。重新建立 session 后应读取同一个项目，
不得因 session ID 变化创建一个空的项目数据根目录。
session 过期、退出登录和 session GC 均不得删除持久项目数据库或文件。
应用业务接口只能操作环境变量绑定的项目，不能凭客户端提交的 owner/workspace ID 越权。

外层用户凭据与应用 Bearer 继续分离；网关不向应用转发外层用户 Cookie 或恢复凭据。
本协议未实现自动应用会话交换，也不替代应用自己的会话鉴权。

## 回收与删除

计算租约绝对 TTL 到期、主动释放或用户退出时，先撤销准入，再停止并删除容器，
释放槽位和算力，保留项目卷。后续可以用新容器、新代次甚至另一槽位挂载同一个卷。
到期停止是硬性的计算资源期限，不等于已有应用 drain 或任务无损迁移能力。

工作台须接入前端租约生命周期模块，在 `pagehide` 通知控制面并持续报告页面心跳。
最后一个页面关闭后按短宽限期回收；关闭通知丢失时按心跳超时兜底；绝对到期时间不续期。
独立标签页使用独立 document UUID，关闭一个标签页不得回收其他仍在使用的页面。
具体页面接口与配置见 `../docs/workspaces.md`。这些事件不删除持久项目数据。

项目连续闲置严格超过 14400 秒才进入数据清理候选。
使用项目的行为包括申请计算租约、成功业务准入和显式项目使用心跳。
登录、列出项目、查询项目元数据、控制面轮询以及容器就绪探测不刷新项目使用时间。

GC 必须确认没有租约或残留槽位引用项目，先原子标记 `deleting`，阻止并发重新打开，
再删除项目卷。失败保留 `deleting` 并重试，不能把失败当作已删除。
挂载中或停止失败而被隔离的项目不删卷，先完成容器清理。
删除完成后清除项目标题等内容元数据，仅保留最小 UUID/时间/状态记录用于生命周期审计。
这不是备份机制，项目过期清理后不提供内容恢复。
