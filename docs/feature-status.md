## 2. 目录与责任边界

```text
runtime-host/
  control-plane/       用户、持久项目、邀请码、调度、容器生命周期、CLI
  gateway/             同源静态资源与受控 API 转发
  deploy/              控制面镜像、Compose 和部署模板
instance-app/
  backend/             容器内业务 HTTP 服务、Runtime Host、插件和存储
  frontend/            通用 Reader、PDF.js 桥接、邀请码入口与租约生命周期模块
  workbench/           完整工作台 HTML、脚本、样式、开发服务器及浏览器测试
  deploy/              应用镜像定义与构建规则
contracts/             两侧共享的版本化 HTTP 和运行协议
docs/                  功能、架构、接口、配置、安全与协作说明
scripts/               本地启动与模块边界检查
```

- 完整前端的受跟踪开发目录为 `instance-app/workbench/`，不是 `sync/` 中的副本。
- 控制面与应用不共享数据库，也不互相导入私有模块。
- 控制面可以自行容器化；“容器外”是相对于用户业务实例而言。
- `reference/`、`sync/`、运行数据、凭据、依赖目录和构建产物不纳入版本控制。

## 3. 用户、项目与持久化

### 3.1 用户身份

- 创建用户时签发 UUID 和恢复凭据，浏览器通过 HttpOnly 用户 Cookie 保持身份。
- 数据库只保存恢复凭据的哈希；UUID 本身不构成访问授权。
- 支持使用 UUID 与恢复凭据重新登录，并恢复查看自己的项目。
- 工作台入口提供恢复登录，用户菜单提供当前身份和本标签页可用的恢复凭据。
- 当前不是邮箱、密码或 OAuth 账号系统；恢复凭据丢失后没有自动找回流程。

### 3.2 多项目与计算分离

- 同一用户可以创建和保存多个 workspace，每个 workspace 对应一个持久项目。
- 每个持久项目使用独立数据卷；新项目的数据目录为
  `users/<owner_uuid>/workspaces/<workspace_uuid>`。
- 容器是临时计算载体，释放容器不会删除持久项目卷。
- 后续申请项目租约时，控制面按 UUID 重新挂载对应数据卷。
- 每个应用实例只服务一个工作区内的项目；应用内 `project.id` 与控制面
  `workspace_uuid` 是不同标识，前端不会把两者混用。
- 工作台接入了持久项目选择、新建与切换。切换计算目标时先释放当前租约。
- 匿名临时租约作为兼容入口保留，释放后按临时卷策略删除数据；不等同于持久项目。
- 旧临时工作区不会被静默迁移或丢弃，需先导出内容再转入持久项目。

### 3.3 独立的有效期

- 计算使用绝对租约期限，到期后拒绝访问并回收计算；页面心跳不延长该期限。
- 项目保留期限写入 `CONTROL_PLANE_WORKSPACE_IDLE_TTL_SECONDS`；当前部署配置为 `inf`，
  因此持久项目永久保留。只有显式删除或管理员清理才会删除。
- 浏览项目列表不自动为所有项目续期；工作台通过受控的项目使用请求记录使用情况。
- 页面存活心跳、项目使用时间和计算到期时间是不同机制。
- 多标签页独立登记，全部页面关闭或失去心跳后回收计算，持久项目数据继续保留。
- 浏览器关闭通知有服务端超时兜底，并存在关闭宽限期和 GC 周期，不承诺瞬时停止。

## 4. 邀请码与槽位分配

### 4.1 严格准入规则

| 配置/输入 | 分配行为 |
| --- | --- |
| `inviteonly=true`，未提供系统邀请码 | 拒绝分配槽位 |
| `inviteonly=true`，提供有效系统邀请码 | 允许申请，并获得最高优先级 |
| `inviteonly=false`，未提供邀请码 | 允许普通优先级申请，有空闲容量时分配 |
| `inviteonly=false`，提供有效系统邀请码 | 优先分配；满载时可抢占低优先级实例 |
| 任意模式，显式提供无效或已撤销的邀请码 | 明确拒绝，不静默降级为普通申请 |
| 输入项目分享字符串 | 只用于复制项目，不能直接作为槽位邀请码 |

- 邀请码输入口始终保留，前端读取访问策略并在每次进入前重新校验。
- TOML 中的 `inviteonly`、`invitationonly`、`invitation_only` 是同一配置的别名，
  不是三个独立开关；环境变量沿用 `CONTROL_PLANE_INVITATION_ONLY`。
- 最高优先级租约不会互相抢占；没有可回收的低优先级实例时仍可能返回满载。
- 系统码已接入 CLI 签发、列表和撤销；也可由受保护配置预置，已撤销码不会因重启复活。
- 系统码包含格式版本和安全随机内容，数据库只存哈希，明文仅在签发时返回。
- 分享导入和历史 trial grant 不再豁免邀请模式；再次提交分配/复用申请也经过准入判定。
- 读取现有租约及普通业务请求不等于重新分配槽位，不要求每个请求重输邀请码。

## 5. 项目分享与独立副本

### 5.1 用户流程

1. 所有者在持久项目中点击右上角分享按钮。
2. 控制面签发绑定该项目的唯一字符串，弹窗提供复制、有效期和撤销操作。
3. 接收用户在入口填写分享字符串，服务端将项目复制到接收者的新 UUID 和新数据卷。
4. 接收者为自己的副本申请计算；邀请模式下仍需有效系统邀请码。
5. 打开副本后可独立修改，源项目不共享挂载，也不会因副本修改而改变。

分享交互只显示可复制的字符串，不生成二维码或分享链接。字符串是不可猜测的复制授权，
不是公开的项目 UUID，也不具备系统邀请码的优先级。

### 5.2 服务端保障

- 只有项目所有者能签发或撤销该项目的分享字符串。
- 只有已声明 `content_only` 布局的项目可作为分享源，防止复制会话或凭据。
- 导入会先停止源项目计算，再复制已落盘数据；源项目数据保留，但进行中的任务可能中断。
- 支持幂等导入，分配容量不足后重试不会不断产生同一份副本。
- 复制失败不发布可使用的半成品，失败和残留状态可被检测及清理。
- 接收者得到独立卷和目录；不能据分享字符串直接访问源项目。
- 复制明确排除会话、鉴权和凭据子树，应用 session 始终放在卷外。
- 克隆启动由控制面注入源工作区和复制操作标识；应用校验后重绑工作区，
  保留文档、节点和其他业务稳定 ID，并支持继续分享副本。
- 新卷的空数据目录由独立、禁网的初始化 helper 交给非 root 应用用户，
  不递归更改已有业务数据的属主，也不把 Docker socket 交给应用。

## 6. 应用会话与网关

- 浏览器用户身份、计算租约和应用 Bearer 是三类独立凭据。
- managed 模式下，用户通过控制面邀请码准入后调用 `/control/app-session`，
  不再输入第二道应用体验码。
- 控制面校验有效租约和受控实例地址，通过每租约、每代次独立的服务端凭据，
  调用实例的内部 session 接口。
- 应用根据自身绑定的 workspace 签发 Bearer；控制面返回前重新检查租约及工作区。
- 引导凭据不返回浏览器、不进入项目数据，网关拒绝公网访问 `/internal/`。
- 未配置或错误引导凭据明确拒绝；没有降级为免鉴权业务访问的路径。
- standalone 本地演示仍可使用原来的应用体验码流程。
- 业务 API、PDF 原件与资源读取继续要求应用 Bearer，令牌不放进 URL。
- 网关同源托管静态资源，根据租约选择受控实例，屏蔽公网管理接口和客户端伪造路由头。

## 7. 文档基础服务与多格式支持

### 7.1 通用文档服务

- 文本创建、文件上传、文档元数据修改及删除。
- 不可变 revision、新版本上传、原件及派生产物元数据管理。
- 原件和二进制资源提供 Bearer 鉴权、HEAD、ETag、Range 和条件读取。
- 文本抽取任务、抽取状态及带版本的结构化文本。
- 统一来源引用解析，绑定文档、revision、抽取版本或构建产物，不静默改指最新版本。
- 格式检测、路径校验、大小限制和工作区边界检查；不能解析时明确返回原因。

### 7.2 格式能力

| 格式 | 后端能力 | 浏览器能力与限制 |
| --- | --- | --- |
| MD/TXT | UTF-8 文本、版本、抽取及文本引用解析 | 安全渲染、原文、搜索、圈选、高亮与节点来源定位 |
| PDF | 原件、结构校验、文本层抽取、引用解析 | PDF.js 原始页面、canvas/文本层、搜索、大纲、选区及页坐标映射 |
| TEX | 单文件与 ZIP 多文件工程校验、入口/资源路径和源码引用 | 通用源码 Reader 模块；尚非完整在线 TEX IDE |
| TEX 编译 PDF | 构建/产物接口及共用 PDF Reader 的契约 | 无安全执行器时编译返回 503，不伪造 PDF 结果 |

- PDF Reader 通过同源自托管的 PDF.js、worker、字体等资源加载，不依赖运行时 CDN。
- PDF 页面支持按需渲染；选区保存统一页坐标，文本引用与真实抽取结果对应。
- 没有文本层的扫描 PDF 不伪造文字或字符偏移；当前没有 OCR。
- TEX 工程拒绝路径穿越、危险归档及非法入口；不在保存模型密钥的应用环境内直接编译。
- 上传和保存 TEX 工程不等于已支持安全编译或完整源码编辑工作流。

## 8. 工作台交互

- 首页、容量/忙碌页面、工作区页面与辅助说明页面。
- 文档列表、文件上传/拖放、新建文本、重命名、删除和标题路径前缀组织。
- 所谓文件夹是文档标题中的逻辑路径，不是服务器上的任意文件系统管理器。
- MD、RAW 和分页视图；真实 PDF 使用专用 PDF 视图，文本的分页版式不冒充原始 PDF。
- 节点创建、编辑、删除、父子结构、连接关系、位置和状态保存。
- 解释提问、历史版本、串讲、回讲、任务状态和取消。
- 文档到节点的来源跳转与高亮，画布缩放/平移、布局、视图切换、搜索和快捷操作。
- 跟随阅读时，画布按文档实际滚动差值逐像素移动；不再采用旧 easing 或按锚点插值。
  切换文档或视图时重置滚动基准，而不是无条件移动画布。
- 自由绘图工具含笔、标记/高亮、橡皮、颜色、撤销与清除；文本笔迹与块关联，
  PDF 笔迹使用页坐标以适应缩放。
- Markdown/JSON 导出使用当前实际业务数据，不以客户端样例代替服务器内容。
- 桌面和移动端布局已在此次准入与分享流程中验收，不代表所有交互都有全平台浏览器覆盖。

### 数据保存范围

| 数据 | 保存位置 | 是否随项目分享复制 |
| --- | --- | --- |
| 文档、版本、节点、连接、解释、串讲、学习数据 | 持久项目文件及数据库 | 是 |
| 控制面用户、租约和邀请码元数据 | 控制面数据库 | 否 |
| 应用 session 和鉴权数据 | 卷外临时目录 | 否 |
| 阅读偏好、部分视图状态、本地高亮和绘图笔迹 | 浏览器本地存储 | 否 |

## 9. 插件、业务工作流与模型

### 9.1 统一插件 SDK

- 插件直接使用 `backend.plugin_contracts`，没有独立的兼容适配层或双套公开协议。
- SDK 提供 manifest、依赖、版本、能力、面板、输入/输出 schema 和生命周期。
- Host 按依赖顺序启动、逆序关闭，并处理启动失败后的清理。
- 工作流统一采用 `WorkflowInput -> Draft`，结果由 Host 提交，不由插件自行落库。
- 未知能力、版本不匹配、重复工作流或缺失依赖等问题会拒绝装配。
- 插件是随构建交付的可信 Python 代码；能力句柄不是可执行任意用户代码的安全沙箱。

### 9.2 已有业务工作流

| 插件 | 工作流 | 当前功能 |
| --- | --- | --- |
| `documents` | 无独立模型工作流 | 文档能力声明，基础服务由 Runtime 提供 |
| `explanations` | `explanation.v1` | 基于节点和有效来源生成解释草稿并保存历史 |
| `knowledge-narration` | `narration.v1` | 按选定节点顺序生成串讲段落及派生时长 |
| `knowledge-narration` | `retelling.v1` | 将已解释子节点回讲到父节点，返回 blocked/partial/complete 状态 |
| `card-clear` | 无模型工作流 | 清除当前文档或框选卡片，并提供服务端撤销快照 |

- 学习资料与节点学习状态可持久化，写入带 revision，陈旧写入返回冲突。
- 回讲要求已设置学习资料、父节点已有解释，并根据子节点解释的可用情况决定结果。
- `GET /api/plugins` 和 `GET /api/runtime` 提供能力发现，不暴露模型密钥。

### 9.3 模型接入

- Fake Provider：确定性离线结果，用于开发与回归。
- OpenAI-compatible Provider：chat completions 协议。
- Gemini Provider：原生 `generateContent`，使用请求头传 API Key，解析候选文本，
  排除思考片段，对异常状态、非 JSON 和不完整输出明确报错。
- 业务插件统一使用请求对象式 `explain`、`narrate`、`retell`，不负责选择 HTTP 协议。
- Gemini 原生接入和 `gemini-3-flash-preview` 已有真实解释任务成功验证；
  最新分享与邀请回归全部使用 Fake Provider，不产生付费模型调用。
- 程序不会因为模型出错而伪造离线答案，或擅自改用其他模型。

## 10. 任务、并发与错误处理

- 任务支持提交、查询、列表、取消、历史及幂等键。
- 模型、抽取和编译编排使用分离的有界执行队列，避免无限排队。
- 模型调用在事务外执行，发布结果前重新检查取消、session 和读取到的数据版本。
- 插件可通过 precommit 检查业务快照；回讲期间树、资料或解释变化会拒绝旧结果。
- 业务实体保存与任务完成状态位于同一事务，完成写入失败会回滚业务结果。
- 重启后的未完成任务标记为中断，不自动重放可能产生费用的调用。
- 错误使用稳定 code/message 信封，浏览器明确展示失败，不将失败替换成演示数据。
- 当前通过轮询获得任务结果。内部事件可记录，但 HTTP SSE 仍返回 501，未交付流式回答。

## 11. 运维、配置与交付

- 控制面支持 TOML 统一配置，并保留环境变量覆盖，缺失或非法配置明确报错。
- 配置优先级为默认值、配置文件、环境变量、显式代码覆盖，后者覆盖前者。
- 容器内应用使用自己的 `TUTORLM_*` 配置；控制面 TOML 不等于整个项目共用一份配置文件。
- CLI 提供健康/容量、槽位、租约、事件、配置摘要、drain、回收、隔离解除、对账和 GC。
- CLI 支持系统邀请码签发/列表/撤销、用户注册/恢复及项目分享/导入。
- 管理命令走控制面 HTTP API，不直接操作业务数据库；没有绕过租约的普通 `slots start` 命令。
- 提供 Fake/Docker 适配器、应用/控制面 Dockerfile、网关及两种 Compose 配置模式。
- 业务实例无宿主端口发布、无 Docker socket，采用非 root、只读根文件系统、
  tmpfs、资源限额和能力收缩；只有控制面持有 Docker 管理权限。
- 完整工作台、通用 Reader 与 PDF.js 资源需要同源一起交付。当前应用 Dockerfile
  不能自动把 `workbench/` 页面全部纳入通用模块的静态制品，发布流水线仍需统一整理。
- 本地开发脚本默认 loopback 和离线模型；CI 分开执行控制面、后端和前端测试。

| 隔离 Docker，邀请模式 | 副本仍需系统邀请码才能分配计算，完整复制流程通过 |
| 浏览器，桌面及移动端 | 开放/邀请入口、分享按钮、字符串弹窗、导入及副本打开通过 |

Docker 验收使用独立资源前缀、测试数据与离线模型；测试栈、测试卷和专用测试镜像已清理。
这不等于生产安全审计、负载压测或所有功能的跨浏览器验收。
